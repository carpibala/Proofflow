# ProofFlow 前端运行说明

本说明适用于仓库中的本地 Demo。前端位于 `frontend/`，使用 Next.js；文档和事件保存在本机 SQLite。当前已支持用户名与密码登录、文档所有权检查，详见 [登录系统说明](authentication.md)。默认仍在本机运行。

## 1. 准备环境

- 安装 **Node.js 24 或更新版本**。项目的 `package.json` 要求 `node >=24`，后端使用 Node 内置的 `node:sqlite`。
- 首次安装依赖需要能访问 npm 软件源。
- 在仓库根目录打开终端，先检查版本：

```powershell
node --version
npm --version
```

Windows 和 macOS/Linux 都直接使用 `npm`，不要写成 `npm.cmd`。若 PowerShell 因执行策略拒绝运行 `npm.ps1`，请改用 `cmd` 终端执行同样的 `npm` 命令，不必修改本文件中的任何命令。

## 2. 安装并启动

在**仓库根目录**执行：

```powershell
cd frontend
npm ci
$env:PROOFFLOW_ORIGIN = "http://127.0.0.1:3001"
npm run dev -- -p 3001 -H 127.0.0.1
```

终端出现 `Ready` 后，在浏览器打开 <http://127.0.0.1:3001/>。保持这个终端运行；结束服务时按 `Ctrl+C`。

**本机运行时必须先设置 `PROOFFLOW_ORIGIN`**，其值要与浏览器地址栏中的来源完全一致（含端口，不带尾部斜杠）。它用于服务端对写请求的 Origin 校验，来源不匹配的写请求会被拒绝。改端口时，`$env:PROOFFLOW_ORIGIN`、启动命令里的 `-p` 和浏览器地址要一起改。macOS/Linux 用 `export PROOFFLOW_ORIGIN="http://127.0.0.1:3001"` 设置同名变量。

`npm ci` 按仓库中的 `package-lock.json` 安装依赖。上述命令的 `cd frontend` 只执行一次；其他终端从仓库根目录重新进入 `frontend/`。`$env:` 设置只在当前终端会话有效，新开终端需要重新设置。

## 3. 使用 Demo

打开页面后可以手动输入、粘贴并查看时间线。“记录”视图读取已保存事件，支持检索、类型筛选、查看修改属性和统计更改、粘贴次数；点击“验证记录”可检查本地数据库中的事件链与最终正文。点击“查看证据报告”会先保存当前待提交编辑，再显示统计。报告页可确认“冻结最终版本”，成功后编辑器变为只读，并可下载 JSON 证据包。在 `frontend/` 运行 `npm run verify:bundle -- <下载文件路径>` 可离线检查包内哈希。没有 AI 助手、证书、数字签名或公钥验证。

SQLite 文件会在使用 API 后创建于 `frontend/data/proofflow.sqlite`，此目录被 Git 忽略。需要保留演示数据时，请保留该文件；重启服务不会自动清空它。浏览器草稿另外保存在当前地址的 `localStorage`。如果切换端口或工作区，草稿的文档 ID 可能不在当前数据库中；此时不要清除网站数据，应先确认原服务和原数据库。

## 4. 可选：检查项目

在 `frontend/` 目录执行：

```powershell
npm test
npm run lint
npm run build
```

运行 API 集成测试时，先在一个终端按第 2 步启动服务，再在另一个终端进入 `frontend/` 并执行：

```powershell
npm run test:integration
```

UI 冒烟测试还需要本机安装 Microsoft Edge、Google Chrome，或 Playwright Chromium。测试会按此顺序自动寻找；也可用 `PROOFFLOW_BROWSER_PATH` 指定浏览器可执行文件：

```powershell
npm run test:ui
```

若没有上述浏览器，可在 `frontend/` 目录执行 `npx playwright-core install chromium` 安装测试用 Chromium。

测试默认连接 `http://localhost:3001`。若服务使用其他端口或仅绑定 `127.0.0.1`，在 PowerShell 中先设置 `$env:PROOFFLOW_TEST_URL = 'http://127.0.0.1:3001'`（按需修改端口），再运行测试。测试会创建演示文档；UI 截图写入被 Git 忽略的 `frontend/data/`。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| `node --version` 低于 24 | 安装 Node.js 24+ 后重新打开终端。 |
| PowerShell 拒绝运行 `npm.ps1` | 改用 `cmd` 终端执行同样的 `npm` 命令；不要写成 `npm.cmd`。 |
| `npm ci` 提示 lockfile 不同步 | 确认使用的是本仓库 `frontend/package.json` 与 `frontend/package-lock.json`，再检查是否有未提交的依赖改动。 |
| 3001 端口已被占用 | 先停止已有服务，或把启动命令中的 `3001` 改为其他端口，同时修改 `PROOFFLOW_ORIGIN`、浏览器地址和测试 URL。 |
| 提示已有 `next dev` 正在运行 | 回到原服务终端继续使用或按 `Ctrl+C` 停止，再启动新服务。 |
| 记录提示“当前服务未找到这份文档” | 草稿仍在浏览器中；检查是否换了端口、工作区或 SQLite 文件。不要直接清除网站数据。 |

后端接口与证据格式详见 [当前证据契约](current-evidence-contract.md)。
