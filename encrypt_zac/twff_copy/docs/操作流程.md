# 傻瓜式操作流程

> 前提：你的终端提示符是 `(mytest)`，说明 conda 环境已经激活。
> **不要用 `$PY` 这种变量**（忘了赋值就会报「&后面的表达式生成无效的对象」），直接写 `python`。
>
> 下面的命令都用**从 `Proofflow` 起的相对路径**。开始前先确保终端在 `Proofflow`
> 目录下（即本项目的根仓库目录，例如 `D:\hacku\teamproject\Proofflow`）。

---

## 第 -1 步：配置环境（一次性，不用装任何包）

### 1. 确认 Python 版本

```powershell
python --version
```

**要求 Python 3.10 或更高。** 原因是代码用了 3.10 才支持的联合类型标注（`str | None`）。
本项目实测过的版本：**3.11.17**（Anaconda `mytest` 环境）、3.12.14。

如果提示 `python 不是内部或外部命令`，说明 conda 环境没激活，先执行 `conda activate mytest`。

### 2. 安装依赖：什么都不用装

**本项目不需要任何第三方 Python 包。** `requirements.txt` 里没有任何包名，
全部代码只依赖 Python 标准库（`argparse` `hashlib` `json` `pathlib` `subprocess` 等）。

所以正常情况下**这一步没有命令要执行**。如果你习惯按流程走一遍，下面这条可以放心执行，
它不会安装任何东西：

```powershell
python -m pip install -r requirements.txt
```

实测输出（exit code 0，什么都没安装）：

```
Defaulting to user installation because normal site-packages is not writeable
Looking in indexes: https://pypi.tuna.tsinghua.edu.cn/simple
```

看到这两行就说明正常——它在索引里没找到任何需要装的包，直接结束。
（`Defaulting to user installation` 是 Anaconda 环境的常规提示，不是错误。）

> 唯一需要额外准备的（**可选，不影响核心功能**）：
> TWFF 参考实现仓库，只用于「跨实现校验」这一步——用它自带的校验器复验本工具产出的
> `audit.json`，证明两边格式互通。它位于 `encrypt_zac\twff\`。
> 它不是 Python 包、无法 pip 安装；不存在时只会少一项交叉验证，
> `init` / `watch` / `announce` / `verify` / `show` 全部照常工作。

### 3. 环境自检（30 秒，确认真的能跑）

```powershell
cd encrypt_zac\twff_copy
python test_diff.py
python chainlog.py verify --log audit.json --file textfile.txt
```

预期输出：

```
============================================================
通过 29 项，失败 0 项

✅ 完整  15 条事件，链未被篡改
```

> 其中「通过 29 项」是 diff 单元测试，必须一项都不失败；
> 第二行的**事件条数会不同**（取决于你的 `audit.json` 已经记了多少条），
> 只要开头是 `✅ 完整` 就说明环境正常。

看到这两个结果，环境就算配好了，可以跳到第 0 步。

⚠️ **这个窗口别关，它会一直挂着监视。** 接下来去开**第二个** PowerShell 窗口做第 4 步。

## 第 4 步：改文件（新开一个终端！）

新窗口里执行（同样从 `Proofflow` 目录起）：

```powershell
cd encrypt_zac\twff_copy
```

然后改 `textfile.txt`。最省事的办法是用记事本：

```powershell
notepad textfile.txt
```

随便加几个字，**保存**，关掉记事本。等 1～2 秒。

**回到第 3 步那个窗口**，应该会多出一行：

```
[2026-10-03T06:31:01Z] content_modified  94 chars (+50)  c27cd038bc4a…  _hash=35150aafceed…
```

再改一次、保存，就会再多一行。**每改一次记一条**，这就是哈希链。

---

## 第 5 步：停止监视

回到监视器窗口，按 **Ctrl + C**。

**看到这样就对了：**

```

```

（如果窗口没反应，直接关掉也行——已记录的事件都在磁盘上，链依然完整，只是少一条 `session_end`。）

## 第 8 步（可选）：亲手篡改一次，看它是怎么被抓住的

### 8a. 先改正文，验证会失败

**看到这样就对了：**

```

     记录 c27cd038bc4a66aa…
     实际 9f1b7e2d3c4a8f01…
```

### 8b. 再篡改日志本身，链会崩

```powershell

```

**看到这样就对了：**

```
  1 改事件字段 (event[3])          ❌ 抓到：event[3] ('content_modified') 哈希不匹配
  2 删除一条事件 (event[4])        ❌ 抓到：event[4] ('content_modified') 哈希不匹配
  3 调换顺序 (event[5]↔[6])       ❌ 抓到：event[5] ('content_deleted') 哈希不匹配
  4 追加伪造事件                   ❌ 抓到：event[8] ('content_modified') 哈希不匹配
  5 篡改后重算整条链                ✅ 未发现（链自洽）   ← 必须靠 anchor.json 才能发现
```

## 常见问题

**Q: 报 `&后面的表达式生成无效的对象`**
`$PY` 是空的。别用变量，直接写 `python`。

**Q: 报 `python 不是内部或外部命令`**
conda 环境没激活。看提示符里有没有 `(mytest)`；没有就先 `conda activate mytest`。

**Q: watch 窗口一直不出现新行**
① 确认改的是**同一个** `textfile.txt`（注意别改到 `textfile1.txt`）；② 确认保存了（记事本要按 Ctrl+S）；③ 文件内容真的变了（改成一样的内容不会记账）。

**Q: 中文乱码**
不用管内容编码，程序按二进制读文件、按 UTF-8 解码展示。预览里的 `?` 是 BOM 或不可打印字符的占位符。

**Q: 我想监视别的文件**
把 `--file textfile.txt` 换成你的文件路径即可，`--log` 也建议换一个名字，例如：
```powershell
python chainlog.py init --file myessay.txt --log essay-audit.json
python chainlog.py watch --file myessay.txt --log essay-audit.json
```

**Q: 每次只记一条，我连改好几下怎么办**
轮询间隔默认 1 秒，间隔内的多次修改会合并成一条事件。想更细就调小：
```powershell
python chainlog.py watch --file textfile.txt --log audit.json --interval 0.2
```
