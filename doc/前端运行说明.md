# ProofFlow 前端运行说明

本说明适用于仓库中的本地 Demo。前端位于 `frontend/`，使用 Next.js；文档和事件保存在本机 SQLite。当前没有登录或权限控制，请仅在本机运行，不要直接开放到公网。

## 1. 准备环境

- 安装 **Node.js 24 或更新版本**。项目的 `package.json` 要求 `node >=24`，后端使用 Node 内置的 `node:sqlite`。
- 首次安装依赖需要能访问 npm 软件源。
- 在仓库根目录打开终端，先检查版本：

```powershell
node --version
npm.cmd --version
```

Windows PowerShell 若提示禁止运行 `npm.ps1`，直接使用下面的 `npm.cmd` 命令，无须修改系统执行策略。macOS/Linux 把 `npm.cmd` 换成 `npm`。

## 2. 安装并启动

在**仓库根目录**执行：

```powershell
cd frontend
npm.cmd install
npm.cmd run dev -- -p 3001 -H 127.0.0.1
```

终端出现 `Ready` 后，在浏览器打开 <http://127.0.0.1:3001>。保持这个终端运行；结束服务时按 `Ctrl+C`。

目前仓库的 `package-lock.json` 与依赖声明不同步，`npm ci` 会报错，因此首次安装使用 `npm install`。安装可能更新本地的 lockfile；提交代码前请检查 `git status`，不要无意提交依赖改动。

## 3. 使用 Demo

打开页面后可以新建文档、手动输入、粘贴、插入服务器保存的示例 AI 回答，以及查看事件时间线。AI 回答是**固定示例**，并非实时调用模型。证书按钮目前仍不可用；Finalize、签名和独立 Verify 尚未接到页面。

SQLite 文件会在使用 API 后创建于 `frontend/data/proofflow.sqlite`，此目录被 Git 忽略。需要保留演示数据时，请保留该文件；重启服务不会自动清空它。

## 4. 可选：检查项目

在 `frontend/` 目录执行：

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run build
```

运行 API 集成测试时，先在一个终端按第 2 步启动服务，再在另一个终端进入 `frontend/` 并执行：

```powershell
npm.cmd run test:integration
```

UI 冒烟测试还需要本机安装 Microsoft Edge 或其他 Chromium 浏览器：

```powershell
npm.cmd run test:ui
```

测试默认连接 `http://localhost:3001`。若服务使用其他端口，在 PowerShell 中先设置 `$env:PROOFFLOW_TEST_URL = 'http://127.0.0.1:3002'`，再运行测试。测试会创建演示文档；UI 截图写入被 Git 忽略的 `frontend/data/`。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| `node --version` 低于 24 | 安装 Node.js 24+ 后重新打开终端。 |
| PowerShell 拒绝运行 `npm.ps1` | 使用 `npm.cmd`。 |
| `npm ci` 提示 lockfile 不同步 | 按第 2 步使用 `npm.cmd install`。 |
| 3001 端口已被占用 | 先停止已有服务，或把启动命令中的 `3001` 改为其他端口，同时修改浏览器地址和测试 URL。 |
| 提示已有 `next dev` 正在运行 | 回到原服务终端继续使用或按 `Ctrl+C` 停止，再启动新服务。 |

后端接口与证据格式详见 [`docs/backend-contract.md`](../docs/backend-contract.md)。
